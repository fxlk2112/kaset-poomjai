ยอดอ่านลด **≈93.8%** ขณะที่จำนวน query ลดเพียง **≈4.8%** และจำนวน claim เพิ่มขึ้น ผลหลักจึงสอดคล้องกับการลดแถวที่อ่านต่อ query หลังเพิ่ม index ไม่ใช่เพียงผู้ใช้งานหายหรือ polling หยุด

อัตรารายชั่วโมงข้างต้นคำนวณโดยนำช่วง 10 นาทีคูณ 6 **ยังไม่ได้สังเกตจริงครบหนึ่งชั่วโมง** และไม่ใช้แทนยอดรายวันหรือบิล ภาพ headline แสดง 78k → 5k แยกต่างหาก ไม่ใช้ตัวเลขนี้คำนวณเปอร์เซ็นต์ของกราฟ

## ความปลอดภัยและข้อจำกัด

- หลักฐาน migration ก่อนหน้าแสดงว่า remote EXPLAIN ทั้งสอง query เลือก queued index และ index เดิมยังครบ รายงานรอบนี้วัด traffic จริงต่อจากหลักฐานนั้น
- Claim P50 อยู่ที่ 0.5 ms ทั้งก่อน/หลัง; expire P50 อยู่ที่ 0.3 ms ทั้งคู่ แต่ expire P99 เพิ่มจาก 0.7 เป็น 3 ms ในตัวอย่างนี้ จึงไม่อ้างว่า latency ดีขึ้นทุกกรณี
- ตัวเลข `k` ใน UI ถูกปัดเศษ เปอร์เซ็นต์ที่คำนวณเป็นค่าประมาณ ไม่ใช่รายการคิดเงินละเอียด
- เวลาตรวจยังผ่าน migration ประมาณ 14 นาที จึงมีข้อมูลหลังแก้ที่ครบและเผื่อช่วงรวบรวมข้อมูลได้เพียง 10 นาที ยังไม่ยืนยันผลระยะ 1–24 ชั่วโมงหรือช่วงใช้งานคำสั่งจริงหนาแน่น
- ไม่ต้องเพิ่ม patch อื่นจากผลรอบนี้ ขั้นติดตามที่เหมาะสมคือเทียบช่วงหลังแก้ครบ 1 ชั่วโมง และ 24 ชั่วโมงด้วยนิยามเดิม โดยไม่เปลี่ยน polling/interlocks เพื่อให้ผลแยกจากปัจจัยอื่น

Cloudflare นิยาม `rows_read` เป็นจำนวนแถวที่ query อ่าน/สแกน และให้ใช้จำนวน query ประกอบการวิเคราะห์ traffic: [Metrics and analytics](https://developers.cloudflare.com/d1/observability/metrics-analytics/)
